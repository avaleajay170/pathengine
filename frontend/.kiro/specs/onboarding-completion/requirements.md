# Requirements Document

## Introduction

The onboarding wizard at `/onboarding` is a 5-step profile-building flow that currently simulates backend interactions. This feature completes the wizard by wiring it to real backend APIs: transcript upload with polling and confirmation, profile persistence, path generation, and duplicate-generation prevention. When the backend is unavailable (`VITE_API_BASE_URL` is not set), the existing simulated behavior must remain fully functional as a fallback.

## Glossary

- **Wizard**: The 5-step onboarding form at `/onboarding` (`src/routes/onboarding.tsx`)
- **Onboarding_Wizard**: The React component `Onboarding` managing the 5-step wizard UI
- **API_Client**: The `api` object from `src/lib/api-client.ts` used for all HTTP calls
- **Profile_Context**: The `useLearnerProfile` hook and `LearnerProfileProvider` from `src/lib/learner-profile.tsx`
- **TranscriptUploadResponse**: API response type `{ uploadId: string; status: "processing" }` returned by `POST /api/v1/profile/transcript`
- **TranscriptStatusResponse**: API polling response with `status: "processing" | "completed" | "failed"`, optional `parsedCourses`, `parsedSkills`, and `error`
- **profileId**: String identifier returned by `POST /api/v1/profile` used to initiate path generation
- **isApiEnabled**: Boolean exported from `api-client.ts` that is `true` when `VITE_API_BASE_URL` is configured
- **onboardingComplete**: Boolean field on `LearnerProfile` that is `true` after a path has been successfully generated
- **Generation_Overlay**: The full-screen loading UI shown during the 4-stage path generation sequence

## Requirements

### Requirement 1: Transcript Upload with Backend Processing

**User Story:** As a learner, I want to upload my transcript and have it automatically parsed by the backend, so that my completed courses and skills are accurately credited without manual selection.

#### Acceptance Criteria

1. WHEN `isApiEnabled` is `true` and a learner uploads a file on Step 3, THE Onboarding_Wizard SHALL send the file to `POST /api/v1/profile/transcript` using a `multipart/form-data` request.
2. WHILE a transcript upload is in progress, THE Onboarding_Wizard SHALL display an upload progress indicator and disable further file input.
3. WHEN the upload request completes successfully, THE Onboarding_Wizard SHALL begin polling `GET /api/v1/profile/transcript/:uploadId` at 2-second intervals until the `status` field is `"completed"` or `"failed"`.
4. WHEN polling returns `status: "completed"`, THE Onboarding_Wizard SHALL display the `parsedCourses` list with each course's title and confidence score, and allow the learner to confirm or reject individual parsed items.
5. WHEN polling returns `status: "failed"`, THE Onboarding_Wizard SHALL display the `error` message from the response and fall back to manual course selection.
6. WHEN a learner confirms parsed courses, THE Onboarding_Wizard SHALL add the confirmed course IDs to the `priorCourses` selection state.
7. IF the upload request returns an error status, THEN THE Onboarding_Wizard SHALL display an error message and allow the learner to retry or proceed with manual selection.
8. WHEN `isApiEnabled` is `false`, THE Onboarding_Wizard SHALL use the existing simulated file-reading behavior unchanged.

---

### Requirement 2: Profile Submission to Backend

**User Story:** As a learner, I want my profile data to be saved to the backend when I generate my learning path, so that the backend can use it to produce a personalized path.

#### Acceptance Criteria

1. WHEN a learner clicks "Generate my learning path" and `isApiEnabled` is `true`, THE Onboarding_Wizard SHALL call `POST /api/v1/profile` with all wizard-captured fields before initiating path generation.
2. THE Onboarding_Wizard SHALL include the following fields in the profile submission body: `name`, `goal`, `targetRole`, `skillLevels`, `completedCourses`, `hoursPerWeek`, `preferredFormats`, and `pace`.
3. WHEN `POST /api/v1/profile` returns successfully, THE Onboarding_Wizard SHALL store the returned `profileId` for use in the subsequent path generation request.
4. IF `POST /api/v1/profile` returns an error, THEN THE Onboarding_Wizard SHALL display an inline error alert on Step 5 and SHALL NOT start the Generation_Overlay.
5. WHEN `isApiEnabled` is `false`, THE Onboarding_Wizard SHALL call `updateProfile()` from Profile_Context and proceed with simulated generation as it does today.

---

### Requirement 3: Path Generation via Backend API

**User Story:** As a learner, I want my learning path to be generated by the backend API so that I receive a real, personalized path rather than a mock one.

#### Acceptance Criteria

1. WHEN a profile is saved successfully and `isApiEnabled` is `true`, THE Onboarding_Wizard SHALL call `POST /api/v1/paths/generate` with the `profileId` returned from profile submission.
2. WHILE the path generation request is in-flight, THE Onboarding_Wizard SHALL display the Generation_Overlay with the existing 4-stage progress animation.
3. WHEN `POST /api/v1/paths/generate` returns successfully, THE Onboarding_Wizard SHALL navigate to `/path/{id}` using the `id` from the response.
4. IF `POST /api/v1/paths/generate` returns an error, THEN THE Onboarding_Wizard SHALL dismiss the Generation_Overlay, display an error alert on Step 5, and allow the learner to retry generation without re-entering data.
5. WHEN `isApiEnabled` is `false`, THE Onboarding_Wizard SHALL use the existing mock generation sequence and navigate to the mock path URL.

---

### Requirement 4: Duplicate Generation Prevention

**User Story:** As a learner, I want to be notified if I have already generated a learning path, so that I do not accidentally create a duplicate and lose my progress.

#### Acceptance Criteria

1. WHEN the Onboarding_Wizard mounts and `profile.onboardingComplete` is `true`, THE Onboarding_Wizard SHALL display a notice on Step 5 informing the learner that a path has already been generated.
2. WHEN the duplicate-generation notice is shown, THE Onboarding_Wizard SHALL provide a link to the learner's existing path.
3. WHEN the duplicate-generation notice is shown, THE Onboarding_Wizard SHALL provide a "Start over" option that, upon confirmation, resets `onboardingComplete` and allows the learner to regenerate.
4. WHEN a learner selects "Start over" and confirms, THE Onboarding_Wizard SHALL call `resetLearner()` from Profile_Context and allow the generation flow to proceed normally.
5. WHEN `isApiEnabled` is `true` and a learner confirms "Start over", THE Onboarding_Wizard SHALL treat the subsequent generation as a new profile submission.

---

### Requirement 5: Fallback Behavior Preservation

**User Story:** As a learner using the app without a backend, I want the onboarding wizard to work exactly as it does today, so that the demo experience is unaffected by missing backend configuration.

#### Acceptance Criteria

1. WHEN `isApiEnabled` is `false`, THE Onboarding_Wizard SHALL preserve all existing step navigation, progress bar, and stepper sidebar behavior without modification.
2. WHEN `isApiEnabled` is `false`, THE Onboarding_Wizard SHALL simulate transcript parsing from uploaded CSV/TXT files using the existing `transcriptCourseIds` function.
3. WHEN `isApiEnabled` is `false`, THE Onboarding_Wizard SHALL execute the existing mock 4-stage generation animation and navigate to the mock path URL.
4. THE Onboarding_Wizard SHALL preserve all existing wizard UX including animations, responsive layout, left stepper sidebar, mobile step counter, and accessibility attributes (labels, `aria-pressed`, `sr-only`, semantic HTML).
